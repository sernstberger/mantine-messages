
Markdown and the assistant live in their own entries, `mantine-messages/markdown` and
`mantine-messages/assistant`, with two optional peers. Install them only if you use those entries;
`mantine-messages` itself never imports them:

## Usage

`Inbox`, `ChatThread` and `Composer` share one set of types: `Conversation`, `Message` and
`MessagesUser`. You bring the data; the components never fetch anything.

<Demo data={demos.messenger} />

## ChatThread

`ChatThread` takes messages oldest first. Consecutive messages from one person within
`groupWindow` (5 minutes by default) share one group, each new day gets a divider, and the
messages of `currentUserId` sit on the right. The status of your last message shows under it.

`ChatThread` scrolls itself (it is a Mantine `ScrollArea`), so give it a height or let it fill a
flex column with `style={{ flex: 1 }}`. It opens at the newest message and follows new ones while
the user is at the bottom, or when they sent the message. While they read older messages it stays
put, and loading older messages at the top never moves the view. Set `autoScroll={false}` to turn
this off.

## Replies

A message with `replyToId` shows the message it answers above its bubble: a caption such as
"You replied to Maya" and a faded copy of the original. A click on the copy scrolls to the
original and flashes it. Pass `onReply` to `ChatThread` to show a reply button beside each message,
then give the chosen message to `Composer` as `replyTo`; it shows a "Replying to" bar, focuses the
box, and calls `onCancelReply` on its close button or Escape.

```tsx
const [replyTo, setReplyTo] = useState<Message | null>(null);

<ChatThread messages={messages} users={users} currentUserId="me" onReply={setReplyTo} />
<Composer
  replyTo={replyTo && { id: replyTo.id, authorName: nameOf(replyTo.authorId), body: getPreview(replyTo) }}
  onCancelReply={() => setReplyTo(null)}
  onSend={(draft) => {
    send({ body: draft.text, replyToId: draft.replyToId });
    setReplyTo(null);
  }}
/>
```

## Actions, reactions and files

`actions` sets the buttons beside each message: built-ins (`'reply'`, `'react'`, `'thread'`,
`'edit'`, `'copy'`) show when their handler is set, and custom items `{ id, label, icon, onClick }`
always show. After three, the rest go in a menu. Reactions and attachments on a message render
under its bubble; pass `onToggleReaction` and `onOpenAttachment` to make them interactive.

## Long threads

Pass `onLoadOlder`, `hasOlder` and `loadingOlder` to load history as the user scrolls up; the view
stays where it was while older messages are added above. `unreadAfterId` draws a "New messages"
line after the last read message.

## Building your own layout

`MessageList` is the engine under `ChatThread`: give it any items with `id`, `authorId` and
`createdAt` and a `renderItem`. It adds date dividers, groups (with `groupWith`), the unread line,
scrolling and jumps.

```tsx
<MessageList
  items={notes}
  groupWith={(previous, note) => previous.authorId === note.authorId}
  renderItem={(note, { groupStart }) => <NoteRow note={note} showName={groupStart} />}
/>
```

Inside `renderItem`, `jumpTo(id)` scrolls to an item and flashes it (`highlighted` is true for 1.6
seconds). To jump from outside the list, for example from a sidebar, pass `controlRef`; it gets
`{ jumpTo }`. `ChatThread`, `TeamThread` and `AssistantThread` take `controlRef` too and pass it to
their list.

```tsx
import { useRef } from 'react';
import { MessageList, type MessageListControl } from 'mantine-messages';

const list = useRef<MessageListControl>(null);

<MessageList controlRef={list} items={notes} renderItem={renderNote} />
<Button onClick={() => list.current?.jumpTo('n42')}>Show the first reply</Button>
```

## Panes

`MessagesShell` puts the panes of a messaging app side by side: `MessagesShell.List` (300px,
change it with `w`), `MessagesShell.Main` (the rest of the width) and `MessagesShell.Aside`
(280px), each optional. It fills the height you give it, draws the borders between panes, and
each pane is a labelled region (`aria-label` names it). `withBorder` and `radius` frame the whole.

The shell measures itself. Below `asideBreakpoint` (960px by default, `0` never) the aside hides
and `MessagesShell.AsideToggle`, which renders nothing while there is room, opens it over `Main`;
Escape or a click beside it closes it. Control it with `asideOpened` and `onAsideOpenedChange`,
for example to open a thread panel as soon as a thread is picked. The Messenger demo above and the
work queue below are built on it.

```tsx
<MessagesShell withBorder radius="lg" h={600}>
  <MessagesShell.List aria-label="Conversations">
    <ScrollArea style={{ flex: 1 }}>
      <Inbox conversations={conversations} value={selected} onChange={setSelected} />
    </ScrollArea>
  </MessagesShell.List>
  <MessagesShell.Main aria-label="Conversation">
    <Group justify="space-between" px="md" py="sm">
      <Text fw={600}>{title}</Text>
      <MessagesShell.AsideToggle />
    </Group>
    <ChatThread messages={messages} users={users} currentUserId="me" style={{ flex: 1 }} />
    <Composer onSend={send} m="sm" />
  </MessagesShell.Main>
  <MessagesShell.Aside>{details}</MessagesShell.Aside>
</MessagesShell>
```

## Team chat

`TeamThread` shows Slack-style rows: avatar, name and time on the first message of a group, and
compact follow-ups whose time shows on hover. It takes `ChatMessage` and `SystemEvent` items;
events such as "Priya joined #launch" are centred lines that break groups. A message with `thread`
shows "12 replies" with the people who answered and calls `onOpenThread`; `editedAt` adds
"(edited)", and `visibility: 'internal'` marks an internal note. On hover each message shows React,
Reply in thread, and a menu with Edit (your own messages) and Copy.

Pass channel messages only; thread replies (messages with `threadId`) go to `ThreadPanel`, which
shows the parent, a reply count and the replies, with your `Composer` as its children. Its title
is an `h2` heading; set `titleOrder` to fit your page's outline.

```tsx
const channelItems = items.filter((item) => 'kind' in item || !item.threadId);
const replies = messages.filter((message) => message.threadId === open?.id);

<TeamThread
  items={channelItems}
  users={users}
  currentUserId="me"
  selectedId={open?.id}
  onOpenThread={setOpen}
/>
{open && (
  <ThreadPanel
    parent={open}
    replies={replies}
    users={users}
    currentUserId="me"
    subtitle="#launch"
    onClose={() => setOpen(null)}
  >
    <Composer onSend={(draft) => reply(open.id, draft)} />
  </ThreadPanel>
)}
```

## Message parts

`Message` is the row `TeamThread` draws, for your own layouts: an avatar column and a content
column. Its parts share one Styles API.

```tsx
<Message compact={!groupStart}>
  {groupStart ? <Message.Avatar name={author.name} src={author.avatar} /> : <Message.Meta>9:41</Message.Meta>}
  <Message.Body>
    {groupStart && <Message.Meta>{author.name} · 9:41</Message.Meta>}
    {note.text}
  </Message.Body>
</Message>
```

## Markdown

`MarkdownBody` from `mantine-messages/markdown` renders GitHub flavoured markdown (tables, task
lists, strikethrough) with Mantine `Typography` styles. It is safe by default: raw HTML shows as
text and never becomes elements, `javascript:` links are dropped, links open in a new tab with
`rel="noreferrer"`, and code blocks show their language and a copy button.

`ChatThread` shows `body` as plain text. Render markdown messages with `renderBody`:

```tsx
import { ChatThread } from 'mantine-messages';
import { MarkdownBody } from 'mantine-messages/markdown';

<ChatThread
  messages={messages}
  users={users}
  currentUserId="me"
  renderBody={(message) =>
    message.format === 'markdown' ? <MarkdownBody>{message.body}</MarkdownBody> : message.body
  }
/>
```

Replace a built-in renderer with `components`, for example code blocks highlighted by
`@mantine/code-highlight`: `<MarkdownBody components={{ pre: HighlightedPre }}>`. Add remark
plugins with `remarkPlugins`; they run after remark-gfm.

## Assistant

`AssistantThread` from `mantine-messages/assistant` is a chat with a model: prompts are compact
bubbles on the right, answers are full width. It renders text with `MarkdownBody`, so it needs the
same two peers.

Each `AssistantMessage` has a `role` (`'user'` or `'assistant'`) and `parts`, rendered in order:
`text` (markdown), `reasoning` and `tool`. Reasoning and tools are collapsible steps; a tool shows
its state (running, done, failed) and, when opened, its input and output as JSON.

To stream, set the answer's `status` to `'streaming'` and update its last part as tokens arrive.
Finished parts are memoized, so only the streaming part renders again, and a cursor blinks at its
end. The list follows the answer as it grows while the user is at the bottom. Finish with
`'done'`, or `'error'` with an `error` text to show an alert with Retry.

```tsx
setMessages((current) => {
  const answer = current[current.length - 1];
  const parts = [...answer.parts];
  const last = parts[parts.length - 1];
  parts[parts.length - 1] = { ...last, text: `${last.text}${token}` };
  return [...current.slice(0, -1), { ...answer, parts }];
});
```

- Stop: pass `streaming` and `onStop` to `Composer`; its send button becomes a stop button
- Regenerate: `onRegenerate(message)` shows Regenerate on the last answer and Retry on an error
- Edit and resend: `onEdit(message, text)` lets the user edit a prompt in place; drop the answers
  after it and ask again

Screen readers: the list is a `role="log"` with `aria-live="off"`, so tokens are not read out.
When an answer finishes, its text goes to a visually hidden status region and is read once.
Errors are read by their alert.

## Work queue (example)

A support work queue built from the package: an example app, not a component. Its source is in
[`docs/demos/WorkQueue`](https://github.com/sernstberger/mantine-messages/tree/main/docs/demos/WorkQueue);
copy what you need. Ticket fields (status, priority, assignee, SLA, snooze) are the app's own
types; the package knows nothing about them.

- Triage: a Mantine `Table` with status, priority, assignee, age and SLA; sort by priority, age
  or SLA; filter by view (Inbox, Snoozed, Closed, All), priority and assignee; search; select
  tickets to assign, tag or close them together
- Timeline: one `MessageList` per ticket with a `renderItem` that draws emails as cards, chat
  messages and internal notes (`visibility: 'internal'`) with `Message` parts, and events as
  lines. An email card opens the full message in a `Modal`
- Composer: `Composer` with Reply and Internal note `modes`; `draft.mode` decides which one is
  added
- Actions: assign, status, priority and snooze until a time; a snoozed ticket leaves the Inbox
  until then. Each change adds an event to the timeline, and the Activity list beside it jumps to
  that event through `controlRef`

<Demo data={demos.workQueue} />

The same app as an email client, built on `MessagesShell`: the ticket list, the open ticket's
conversation and its details side by side. Both layouts share one hook (`useWorkQueue`) for the
tickets, filters, sort, selection and bulk actions.

- List: one row per ticket with the customer and the time of the newest message, the subject, a
  preview of the newest email, chat message or note, then priority, SLA and assignee. Unread
  tickets are bold with a dot; opening one reads it. Arrow keys move between rows
- Toolbar: search, sort and a Filters popover over the view switch; while rows are selected
  (checkboxes show on hover and focus) a compact bar to assign, tag or close takes its place
- The open ticket stays open when you close or snooze it, until you pick another. Below 960px the
  details collapse behind a Details button in the ticket header

## Inbox

`Inbox` lists conversations with a preview of the last message, its time and an unread count.
Use `value` and `onChange` to control which one is open, or `defaultValue` to leave it to the
component.

`withSearch` adds a search box that filters by title (`search`, `defaultSearch` and
`onSearchChange` control it). `sections` groups the list: `true` gives Pinned, Channels and Direct
messages from `pinned` and `kind`, or pass `{ id, label, match }` objects; each conversation goes in
the first section that matches. Channels show a `#`.

## Composer

`Composer` grows with its text up to `maxRows`. Enter sends, Shift+Enter adds a line. `onSend`
gets a draft: `{ text, format, attachments, replyToId }`, with the text trimmed.

`modes` adds a switch above the box, for example Reply and Internal note; the chosen `value` goes in
`draft.mode`. A mode with `note: true` tints the composer yellow, and its `placeholder` replaces the
usual one.

```tsx
<Composer
  modes={[
    { value: 'reply', label: 'Reply' },
    { value: 'note', label: 'Internal note', color: 'yellow', note: true, placeholder: 'Only teammates see notes' },
  ]}
  onSend={(draft) => send({ body: draft.text, visibility: draft.mode === 'note' ? 'internal' : 'public' })}
/>
```

The text box is reachable like a Mantine input's: `inputRef` gets the `textarea` (to focus it after
a click elsewhere), `textareaProps` goes to the `Textarea` (`name`, `maxLength`, `autoFocus`,
`onPaste` and so on; its `onChange` and `onKeyDown` run after the composer's own), and `readOnly`
keeps the text selectable but stops editing and sending.

```tsx
const inputRef = useRef<HTMLTextAreaElement>(null);

<Composer inputRef={inputRef} textareaProps={{ maxLength: 2000, onPaste: attachPastedFiles }} />
```
